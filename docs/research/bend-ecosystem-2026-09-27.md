# Bend ecosystem review for the voxel engine (2026-09-27)

This review uses the [Awesome Bend catalog](https://github.com/777genius/awesome-bend/blob/c5a344553ccb0b01f4c110c2319427457fcad241/README.md), [BendHub](https://hub.bend-lang.com/), and the authors' repositories. It evaluated possible uses against the project's then-current Bend 2.0.31, sparse cuboid trees, native Vulkan renderer, and [stress workload](../../scripts/benchmark_stress.py). The project now uses Bend 2.0.32.

## What the current workload says

The current implementation has separate costs for static presentation, edited surfaces, and large body-list edits. The relevant paths are [spatial.bend](../../src/spatial.bend), [world.bend](../../src/world.bend), and the [native bridge](../../src/vulkan/bridge.c). Use the [stress suite](../stress-benchmark.md) for fresh measurements before selecting an optimization target.

## Prioritized findings and proposed experiments

| Priority | Verified source finding | Fit and proposed test | Cost and limit |
| --- | --- | --- | --- |
| **1. Localize work on edits** | [Bend2Craft](https://github.com/lennix1337/bend2craft/blob/c66bfb176a7ce15a4fb97086d5a9100730d22727/README.md) reports **4.97 ms** to rebuild an edited chunk and boundary neighbors, versus **15.43 ms** for all nine chunks. It also buckets entities by chunk before simulation. These are results from its browser/JavaScript/WebGL design, not this engine. | First profile how many bodies and cuboid leaves each cut actually reaches in our [carve preparation](../../src/world.bend). `S.cut` already prunes by tree bounds, but preparation still visits every body; a body-level spatial index could avoid those visits if the scene gains many moving fragments. Separately, prototype region-level surface invalidation around an edit and compare with the full `S.faces` rebuild. Require identical occupied cells, exposed faces, and protected anchors; compare carving, surface generation, accepted-edit p95, and total frame p95. | Medium to high: moving fragments require index updates, and faces crossing regions need boundary invalidation. A broad-phase index is the smaller first experiment. Bend2Craft's timings do not predict our speedup. |
| **2. Make algorithm comparisons output-exact** | [Bend Voxel Bench](https://github.com/OkeyAmy/bend-voxel-bench/blob/515c5bef20faf24c100c1794e410bcd2b98d0b8d/README.md) ports Luanti terrain and checks all 640,000 generated columns against C++ before reporting time. Its [results](https://github.com/OkeyAmy/bend-voxel-bench/blob/515c5bef20faf24c100c1794e410bcd2b98d0b8d/RESULTS.md) separate the comparable one-thread terrain work from Luanti's broader end-to-end queue and liquid work, and flag noisy runs. | For any new culling, meshing, or connectivity algorithm, replay fixed edit seeds through baseline and candidate, compare sorted material/volume and faces, then use the existing stress cases for stage and frame timing. Record compiler, code revision, host, warm-up, run count, and failures. This is a proposed harness improvement, not a measured engine optimization. | Low to medium. Canonicalizing equivalent cuboid partitions takes care; identical occupancy and surface are better invariants than identical tree shape. Its Bend 2.0.27 CPU Bend3D FPS is not comparable with our previously measured Bend 2.0.31 Vulkan FPS. |
| **3. Revisit parallel primitives only for a flat data path** | [bend-parallel](https://github.com/costamatheus97/bend-parallel/blob/45a161a2150da615eff11c8cc39e26ff36bc05a0/README.md) offers in-place `Array<U32>` scans, histograms, stable counting-sort permutations, and gather. It checks results against sequential references and supports CPU threads and Bend's GPU lane; the author publishes **no quiet-machine performance numbers**. | Keep it on the list if face generation becomes a large flat-array pipeline needing compaction or material buckets. A small isolated trial should include conversion and buffer-reuse costs, then compare surface-generation and accepted-edit times under Bend 2.0.32. | High for the current `List<Face>`/cuboid-tree path. Padding to power-of-two arrays and 2^b × bucket-count scratch space may outweigh parallel work. It does not replace the Vulkan renderer or address fence waits. |
| **4. Use packages when a matching feature is scheduled** | [bend-collections](https://github.com/Giulio2002/bend-collections/blob/67fcc9185704fa691f64bedd6f0e8c1a5eac41c9/README.md) now includes a dynamic array, queues, tree/hash maps, an intrusive list, LRU, bitsets, math, and hashes. Its own [benchmarks](https://github.com/Giulio2002/bend-collections/blob/67fcc9185704fa691f64bedd6f0e8c1a5eac41c9/BENCHMARK.md) compare identical workloads/checksums with optimized C; the String-key hash map is much faster than `Base.Map` in that benchmark, but our body cache uses numeric IDs in C and our flood uses a stack-like list. | If a future scheduler needs stable handles and frequent body transfers, trial the intrusive list against the current body list with a dedicated many-fragment test. If persistence is added, evaluate Hub [bend-kit bytes/JSON](https://github.com/paymog/bend-kit/blob/691ad68a5e764a9f16e33319354b79935e2ed3da/README.md) for the *file format*, not the render loop. | Medium to high for data model changes; no measured benefit here. `bend-collections` pins Bend 2.0.28, so first run a 2.0.32 compatibility check. |
| **5. Keep dynamic voxel lighting as a separate future study** | Bend2Craft documents bounded torch-light flood fill and dirty light patches: its cached 421-cell plane patch measured **3.3 ms** versus **44.6 ms** full regeneration for one source, with regression checks against full-chunk light. [Source and measurement](https://github.com/lennix1337/bend2craft/blob/c66bfb176a7ce15a4fb97086d5a9100730d22727/README.md). | If emissive voxels or many movable point lights become a requirement, test an editable light field and dirty-region propagation. Compare the result to full recomputation after cuts, across boundaries and alternate paths. | High. The current engine has sun shadows and a camera work light, but no per-voxel light field; Bend2Craft's grid and browser timings do not transfer directly to sparse cuboids and Vulkan. |

## Hub and release details

On 2026-09-27, the live [Hub statistics endpoint](https://hub.bend-lang.com/stats.json) returned **307 package snapshots and 41 claimed names**, up from 160 and six in the earlier review. Searches for [`voxel`](https://hub.bend-lang.com/search.json?q=voxel), [`mesh`](https://hub.bend-lang.com/search.json?q=mesh), [`spatial`](https://hub.bend-lang.com/search.json?q=spatial), [`octree`](https://hub.bend-lang.com/search.json?q=octree), and [`physics`](https://hub.bend-lang.com/search.json?q=physics) returned empty `names` and `packages` arrays. This is only a search of indexed names, descriptions, and file metadata; it does not prove that no relevant source exists. The [Awesome Bend catalog](https://github.com/777genius/awesome-bend/blob/c5a344553ccb0b01f4c110c2319427457fcad241/README.md) usefully exposes projects such as Bend2Craft and Bend Voxel Bench that are not found by those Hub terms.

The published `bend-collections` import [hash `0x9ee2e9a299991dcc089fe22c7f3ceb5f`](https://hub.bend-lang.com/0x9ee2e9a299991dcc089fe22c7f3ceb5f/main.bend) is immutable and contains the older dynamic-array, map, queue, LRU and hash modules. The current [GitHub README](https://github.com/Giulio2002/bend-collections/blob/67fcc9185704fa691f64bedd6f0e8c1a5eac41c9/README.md) also lists `intrusive_doubly_linked_list.bend`, `bitlist.bend`, and `math/generic.bend`, but those paths return 404 under that published hash as checked on this date. Use the hash for modules it actually contains; a trial of newer modules needs a pinned source checkout or a new published hash. Hub [content-hash imports](https://hub.bend-lang.com/) keep a trial reproducible.

No external package was imported and no engine optimization was implemented in this review. The table separates upstream measurements from experiments proposed for this repository.
